# BLE OTA: обновление Pip-KeyPet без кабеля

Это экспериментальная функция форка. USB Web Serial по-прежнему остаётся способом первоначальной установки и восстановления.

## Первичная установка и использование

1. На компьютере открой `https://666cossack999.github.io/Pip-KeyPet/` в Chrome/Edge.
2. Впервые **прошить по USB**: обновятся bootloader, таблица разделов и приложение с BLE OTA. Перед первым обновлением рекомендуется сохранить важные пользовательские настройки.
3. Последующие обновления: держи Пипа бодрствующим, заряд ≥50% либо питание USB. Если включён ECO, при погасшем экране Bluetooth отключается; разбуди Пипа.
4. Открой веб-панель:
   - на ПК — Chrome/Edge с Web Bluetooth;
   - на iPhone — [Bluefy](https://bluefy.app/) (браузер с Web Bluetooth). Обычный Safari без расширения не поддерживает Web Bluetooth.
5. В разделе **«Прошить / обновить»** нажми **«Обновить по Bluetooth»**.
6. Выбери `Pip`, подтверди цифровое сопряжение на телефоне и брелоке верхней кнопкой (если появится запрос).
7. Оставь приложение на переднем плане, дождись подтверждения записи и перезагрузки.

При установке через OTA передаётся **только образ приложения** (первый `app.bin` из опубликованного релиза, адрес `0x20000` в USB-пакете). Это НЕ способ изменить bootloader, таблицу разделов или размер слотов OTA. Такие обновления выполняются по USB.

## Защита от повреждения прошивки

- В Flash выделены `ota_0` и `ota_1` (по 4 МБ). ESP-IDF записывает данные в неактивный слот через `esp_ota_write`.
- Запись идёт подтверждёнными GATT пакетами. Протокол работает даже при BLE ATT MTU 23: управляющие пакеты максимум 17 байт, блоки приложения адаптивные.
- Перед переключением слота сверяется SHA-256 всех переданных байтов, затем `esp_ota_end` проверяет образ приложения.
- Только после успеха происходит `esp_ota_set_boot_partition`; далее устройство перезагружается по отдельной команде.
- При обрыве до завершения OTA операция отменяется, прежняя прошивка остаётся активной.
- Настройки, состояние питомца и привязка iPhone лежат в NVS: OTA не перезаписывает их.
- `CONFIG_BOOTLOADER_APP_ROLLBACK_ENABLE=y`: загрузчик может откатить обновление, которое не смогло успешно запуститься. Новая прошивка подтверждает старт после инициализации дисплея/интерфейса/задач.
- Требуется шифрованное authenticated BLE-соединение с MITM-защитой для управляющих команд и передачи бинарника. OTA не разрешён при низком заряде.

**Ограничение безопасности:** SHA-256 здесь проверяет целостность доставки, а не происхождение прошивки. Для криптографической гарантии авторства нужны Secure Boot, политика подписи и управление ключами. Не включай Secure Boot/Flash Encryption на устройстве без отдельного плана восстановления.

## BLE GATT, версия 1

| UUID | Роль |
|---|---|
| `50495044-4f54-412d-4b45-595000000001` | Primary OTA service |
| `...00000002` | Control — authenticated write with response |
| `...00000003` | Data — authenticated write with response |
| `...00000004` | Status — read (публичная диагностика) |

Команды:
- `01` + размер приложения (uint32 little endian) — начало сеанса;
- `05` + первые 16 байт SHA-256 и `06` + последние 16 байт — ожидаемая контрольная сумма;
- `Data`: строго последовательные байты бинарника (подтверждение только после записи во Flash);
- `02` — закончить, проверить SHA-256 и образ, переключить boot slot;
- `03` — отменить незавершённое обновление;
- `04` — перезагрузиться после подтверждённого FINISH.

Status — 10 байт: `state:u8, error:u8, received:u32le, total:u32le`, где state = 0 idle, 1 writing, 2 ready, 3 error.

## Проверки перед слиянием в main

CI: сборка ESP-IDF 5.5.5, симулятор `sim/check.py`, `tools/test-ble-ota.mjs`. Требуется реальное аппаратное тестирование:

- Чистый USB flash, затем BLE-подключение с Windows/Chrome и iPhone/Bluefy.
- Сопряжение c numeric comparison и сохранённым bond; проверить старые ANCS/AMS и HID.
- OTA при ECO, экране вниз, во время питания USB, с зарядом 49% и 50%.
- Прервать передачу (Bluetooth off/закрыть приложение), перезапустить: старая версия должна работать.
- Подменить один байт OTA: FINISH должен отклонить неправильную контрольную сумму.
- Проверить успешную загрузку, версию, сохранение NVS и откат при специально неработоспособном образе **на тестовой плате**, а не на основном брелоке.
